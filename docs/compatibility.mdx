## Capability contract

Every compatible kind discovered from the live registry must satisfy every applicable
generic capability and scenario. Behavior rows define the API and operational
requirements used to generate those conformance runs.

| Capability | Requirement |
| --- | --- |
| `components` | Grouped Nodes and chassis expand into visible application containers with validated namespace ownership. |
| `configuration` | Startup configuration, variables, licenses, certificates, and vendor file transformations are preserved. |
| `connectivity` | Every Link flavor has ordered, live, restart-safe, and cleanup-safe direct realization. |
| `entry-path` | Direct resources, Topology, and clabverter produce equivalent labs. |
| `filesystem` | Payloads, binds, tmpfs, shared memory, and persistence have defined direct-Pod semantics. |
| `image-pull` | The kubelet pulls device images with native policy and Secrets while c9s resolves metadata. |
| `kind-plan` | A deterministic direct-runtime plan covers the kind's default realization; detailed behavior capabilities remain to be inventoried. |
| `lifecycle` | Post-start, restart or recreate policy, save, and lifecycle actions target direct containers. |
| `management` | Management addressing, routes, DNS, and exposure are directly realized. |
| `operations` | Logs, exec, events, save, and packet capture operate on direct containers and interfaces. |
| `process` | Images, entrypoints, commands, users, environment, ports, and stop behavior are planned and realized. |
| `readiness` | Preparation, containers, components, connectivity, image health, and probes contribute to readiness. |
| `resource-policy` | Application and component resources and scheduling policy are represented in Kubernetes. |
| `security` | Devices, capabilities, privilege, security profiles, and sysctls are enforced or rejected. |

## Baseline updates

A containerlab version change is an explicit compatibility event. Update the pinned
module identity and dependency lock data together. `make verify-containerlab-compatibility`
validates that identity and discovers the registry live; additions and aliases do not
require c9s catalog edits. Generic behavior gaps still fail conformance.
