# Fix #372 — keysight_ixia-c-one steals sidecar infra interfaces

Problem
- `keysight_ixia-c(-one)` entrypoint `ixiacd` enumerates every interface in its
  netns and `LinkSetNsFd`-moves it into sibling traffic-engine containers,
  filtering only `lo`/`eth0`/`docker0`. In the shared-Pod direct runtime this
  includes sidecar-owned `c9s0` (renamed CNI transport + Pod IP), `c9sr0`/
  `c9sm0` (interposition router leg + mesh VTEP) and every `c9ss*` fabric leg.
  Once `c9s0` leaves the Pod ns `linkByAddress` fails, `clabwire` crash-loops
  on `cannot assign requested address`, device stays `HelperNotReady`.

  Issue: https://github.com/clabernetes/clabernetes/issues/372

Fix
- Add explicit reusable profile switch for the case above:
  `NodeProfile.spec.deployment.networkIsolation: Disabled|Enabled` mirrored as
  `Topology.spec.deployment.networkIsolation`. Omitted → `Disabled` (legacy).
  Topology compilation carries value into emitted NodeProfiles unchanged.
  Standalone Node path synthesizes resolution-level default in
  `controllers/node/profile.go:ResolveProfile()` for the `keysight_ixia-c(-one)`
  family when no explicit value is set (explicit always wins). No planner/codec
  changes; planning stays kind-agnostic.
- Plumb field through `compiler/{input,compile,render}.go` (+ deployment policy
  grouping) and resolve into `ResolvedProfile.NetworkIsolation`.
- Scaffold e2e coverage as generic startup test `TestIxiac`
  (`e2e/topology/direct/ixiac_test.go` + fixtures `60-ixiac.yaml`,
  `61-ixiac-default.yaml`) — explicit-profile proxy validates linux dataplane
  stays intact with isolation enabled; implicit-kind stand-in polls Deployment
  spec for future `device-netns` volume (PENDING until runtime slice lands).
  Light traffic assertions can extend this same test without renaming.

Implementation
- CRD/API: `apis/v1alpha1/{nodeprofile,topologyspec}.go` + deepcopy/OpenAPI/CRDs
  regen (`charts/.../crds/*` + `assets/crd/*` + `generated/openapi/*`).
- Compiler: passthrough of new Deployment policy into NodeProfile rendering;
  profile grouping key prep for distinct isolation modes.
- Controller: `ResolvedProfile.NetworkIsolation` + central `isIxiaKind()` predicate
  + implicit ixia-c→Enabled fallback in ResolveProfile (both nil-profile and
  post-apply cases).
- E2E: neutral-named `TestIxiac` with two subtests as above; explicit case PASS
  in 38s, CRD serving verified, manager upgraded to `local-4a9a6634`.

Follow-up
- Renderer gating of `device-netns` emptyDir mounts at `/var/run/netns`,
  `internal/directruntime/devicenetns_linux.go` lifecycle (bound file, not just
  FD, shared mount), cross-ns `LinkSetNsFd` moves for mgmt+fabric legs, launch
  `setns(CLONE_NEWNET)` enter before `Exec`, and flip second subtest from
  PENDING to Fatal once renderer emits the volume. Real `ixia-c-one:1.61.0-9`
  single-node e2e then goes Ready without CrashLoopBackOff.
